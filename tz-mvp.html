Техническое задание
на MVP системы фонда

Документ описывает минимально достаточный продукт для автоматизации ключевого процесса фонда brainbox_I: Monthly Update портфельного стартапа с AI-матчингом ментора.

Срок: Кандидат определяет самостоятельно и указывает его в ответе на задание. Срок — часть оценки.
Хостинг: Selectel (российское облако). CTO определяет конфигурацию.

Контекст и цели

Фонд brainbox_I — венчурный фонд с 5 портфельными стартапами и базой из 80+ менторов. Центральная идея фонда: каждый стартап получает профильного ментора-партнера, который защищает инвестицию своей экспертизой.

Боль, которую решает MVP: менторы проводят ежемесячные звонки с фаундерами, но результат звонка нигде не фиксируется, гипотезы роста не формализуются, а подбор дополнительных экспертов из базы происходит вручную и бессистемно.

Ключевой кейс MVP
1
Ментор-партнер проводит созвон с фаундером
По стандартному списку вопросов фонда. Созвон записывается или транскрибируется внешним сервисом.
2
Ментор загружает транскрипт в систему
Загружает .txt файл на страницу Monthly Update портфельного стартапа.
3
AI-агент анализирует транскрипт (Claude API)
Выделяет запросы фаундера, формулирует гипотезы роста, определяет ключевые барьеры.
4
AI сопоставляет гипотезы с базой менторов
Находит релевантных экспертов из 80+ анкет (партнеры и независимые) с процентом совпадения и обоснованием.
5
Результат виден на странице Monthly Update
Summary звонка · Риски · Следующие шаги · Список рекомендованных менторов.

Границы MVP

Что входит в MVP, а что остаётся за рамками. CTO обязан реализовать всё из раздела IN SCOPE.

✓ In Scope — делаем
  • Публичная форма фаундера без регистрации
  • Email-регистрация ментора с одноразовым паролем
  • Профиль ментора (заполнение анкеты из 17 вопросов)
  • Каталог менторов — публичный
  • Панель администратора (управление ролями)
  • Страницы портфельных стартапов

  • AI-матчинг гипотез с анкетами менторов
  • Страница Monthly Update с результатом AI
  • Импорт начальной базы менторов (CSV → БД)
  • Защита формы фаундера от спама (captcha или honeypot)
✗ Out of Scope — не делаем
  • Мобильное приложение
  • Push-уведомления
  • Чат внутри системы (используем внешние каналы)
  • Интеграция с календарем
  • Автоматическая транскрибация аудио
  • Оплата и финансовые транзакции
  • Доступ фаундера в систему после подачи заявки
  • Публичные страницы отдельных стартапов
  • Аналитика и дашборд фонда
  • API для сторонних интеграций

M1 · Форма заявки фаундера

Публичная анкета на отдельной странице. Доступна без регистрации. После отправки — экран подтверждения без дальнейшего доступа.

Важно: фаундер после отправки заявки не получает доступ в систему. Никакого кабинета, никаких уведомлений. Это сознательное решение фонда для MVP.

Защита от спама

Реализовать одно из двух на выбор CTO:

  • Honeypot-поле: скрытое поле website — если заполнено, заявка игнорируется. Простое и бесплатное.
  • Google reCAPTCHA v3: невидимая защита, score < 0.5 — отклонить. Требует Google API ключ.

После отправки: заявка сохраняется в БД со статусом pending. Пользователь видит страницу "Ваша заявка принята". Больше ничего не происходит.

M2 · Регистрация и профиль ментора

Регистрация только по email. Вместо постоянного пароля — одноразовый код на каждую сессию (magic link или OTP-код).

Флоу регистрации

1
Страница регистрации
Поля: Имя, Фамилия, Email. Никакого пароля.
2
Система отправляет письмо с 6-значным OTP-кодом
Код действует 15 минут. Только для одной сессии — после входа инвалидируется.
3
Ментор вводит код
3 попытки, затем блокировка на 5 минут. После успеха — сессия авторизована.
4
Анкета профиля
При первом входе — обязательное заполнение анкеты из 17 вопросов. Без этого остальной интерфейс недоступен.
5
Статус: pending
Ментор зарегистрирован, но роль (независимый/партнер) присваивает Администратор вручную. До присвоения — ограниченный доступ.
Повторный вход: каждый раз через email + новый OTP-код. Постоянный пароль не хранится. Это упрощает систему и повышает безопасность для MVP.

M3 · Каталог менторов

Публичная страница. Доступна всем без регистрации. Отображает карточки менторов из базы. Стартовый набор — 80+ анкет из CSV-файла, который загружает Администратор при первом запуске.

Карточка ментора в каталоге

  • Имя и Фамилия (qm1)
  • Должность и компания (qm4)
  • Сильные стороны / компетенции (qm5)
  • Отрасли опыта (qm8)
  • Темы помощи (qm12)
  • Город (qm3)
  • Готовность к созвонам (qm13) — иконка-индикатор
  • Роль: Партнер фонда / Независимый эксперт badge
Не показывать публично: email ментора, Telegram, ответы на вопросы qm15 (инвестиции), qm16, qm17, qm18. Контакт — только через кнопку внутри системы.

Фильтрация каталога

  • Фильтр по отрасли (qm8, qm11)
  • Фильтр по теме помощи (qm12)
  • Фильтр: Партнер / Независимый
  • Поиск по имени или компании

M4 · Панель администратора

Отдельный защищённый раздел для сотрудников фонда. Доступ по отдельным учётным данным.

Функциональность

Управление менторами
  • Список всех зарегистрированных менторов
  • Изменение роли: pending → независимый → партнер
  • Просмотр полной анкеты ментора
  • Импорт CSV → начальная загрузка базы
  • Ручное добавление ментора
Управление стартапами
  • Список всех заявок фаундеров
  • Просмотр анкеты фаундера
  • Изменение статуса: pending → portfolio
  • Назначение ментора-партнера на стартап
  • Создание страницы стартапа вручную

M5 · Monthly Update — страница стартапа

Центральная страница системы. Доступна только ментору-партнеру, назначенному на стартап, и Администратору.

Состав страницы

  • Шапка стартапа: название, категория, дата входа в портфель, ментор-партнер
  • Блок загрузки транскрипта: drag-and-drop или кнопка выбора .txt файла
  • Блок AI-анализа: появляется после загрузки и обработки (статус: загружается → готово)
  • Журнал обновлений: хронологический список прошлых Monthly Updates с датами

Блок AI-анализа (после обработки)

  • 📋 Summary звонка — краткий пересказ 3–5 предложений
  • ⚠️ Выявленные риски — список угроз и проблем, упомянутых фаундером
  • 🙋 Запросы фаундера — конкретные просьбы о помощи
  • 💡 Гипотезы роста — 1–3 сформулированных гипотезы в формате "Для роста нужен эксперт по X"
  • → Следующие шаги — рекомендованные действия от AI
  • 🤖 Матчинг менторов — список из 3–5 экспертов по каждой гипотезе (см. M6)
UX-требование: пока AI обрабатывает транскрипт, показывать skeleton/loader с текстом "AI анализирует разговор…". Обработка не должна блокировать UI — реализовать асинхронно (job queue или polling).

M6 · AI-агент матчинга

🤖 Как работает AI-агент

Два последовательных вызова Claude API. Используется модель claude-sonnet-4-5 или новее.

1
Анализ транскрипта → структурированный вывод
На вход подаётся текст транскрипта. AI возвращает JSON с полями: summary, risks[], founder_requests[], growth_hypotheses[], next_steps[]
2
Матчинг гипотез с анкетами менторов
На вход подаётся каждая гипотеза роста + весь список анкет менторов (поля qm5, qm6, qm8, qm11, qm12). AI возвращает ranked список: ментор, score (0–100), reasoning.

Системный промпт — Шаг 1 (анализ транскрипта)

Ты — аналитик венчурного фонда brainbox_I. Проанализируй транскрипт ежемесячного звонка ментора с фаундером стартапа.

Верни ответ строго в JSON-формате:
{"summary": "...", "risks": ["..."], "founder_requests": ["..."], "growth_hypotheses": ["Для роста нужен эксперт по X, потому что Y"], "next_steps": ["..."]}

Гипотезы роста формулируй в формате: "Для масштабирования [название стартапа] нужен эксперт по [конкретная область], потому что [проблема]". Выдели 1–3 гипотезы. Не выдумывай — только то, что есть в тексте.

Системный промпт — Шаг 2 (матчинг менторов)

Ты — AI-ассистент венчурного фонда brainbox_I.

Гипотеза роста стартапа: {hypothesis}

Ниже — список менторов фонда с их анкетами. Для каждого ментора оцени релевантность по шкале 0–100 и объясни, почему он может помочь именно с этой гипотезой.

Верни JSON: [{"mentor_id": 1, "score": 92, "reasoning": "...", "key_matches": ["...", "..."]}]

Покажи только менторов со score > 60. Отсортируй по убыванию score. Максимум 5 менторов на гипотезу. Обоснование — конкретно, без воды.

Ограничения и обработка ошибок

  • Максимальный размер транскрипта: 100 000 токенов. Если больше — разбить на части с перекрытием.
  • Если Claude вернул не JSON — повторить запрос до 3 раз, затем показать ошибку.
  • Хранить raw-ответ API в БД рядом с обработанными данными для дебага.
  • Все вызовы API логировать с временем, моделью, токенами (мониторинг расходов).

Импорт начальной базы менторов

В распоряжении фонда есть CSV-файл с 80+ ответами менторов (реальные данные). Структура колонок: ID; tg_name; cl_id; cur_date; first_datetime; q1…q17 — соответствуют полям qm1–qm17.

Задача CTO: реализовать скрипт импорта CSV → таблица mentors. Запускается один раз при первичном развёртывании. CSV предоставит фонд. Дубликаты (одинаковый tg_name) — пропускать.

Claude API — технические детали

ПараметрЗначение
ПровайдерAnthropic Claude API (anthropic.com)
Рекомендуемая модельclaude-sonnet-4-5 или актуальный Sonnet на момент разработки
Вызов №1 (анализ)~2 000–8 000 токенов вход, ~500–1 000 токенов выход
Вызов №2 (матчинг)~4 000–12 000 токенов вход (все анкеты), ~500–800 токенов выход
Формат ответаJSON, принудительно через response_format или system prompt
Хранение ключаEnvironment variable ANTHROPIC_API_KEY, не в коде
КэшированиеРекомендуется Prompt Caching для анкет менторов (они не меняются)
Таймаут60 секунд на вызов, 3 retry с exponential backoff
Оптимизация расходов: список анкет менторов — статичные данные. Используйте Anthropic Prompt Caching для кэширования контекста с анкетами между вызовами. Это снизит стоимость матчинга на 70–90%.
